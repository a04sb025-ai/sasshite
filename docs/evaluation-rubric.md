# 自律改善 評価基準

この文書は、AIが変更を「改善」と判断するための共通基準です。点数は絶対評価ではなく、同じ条件でのBefore / After比較に使います。

## 基本ルール

各軸を0〜10点で評価します。総合100点を上限とします。

自動テストが通っただけでは改善とみなしません。対象軸が改善し、重要な回帰がないことを確認します。

## 評価軸

### 1. 初見理解

- 何を見ればよいか分かるか。
- 説明を増やさなくても状況を把握できるか。

### 2. 操作の分かりやすさ

- タップ / ドラッグ / 長押し等の対象が自然に分かるか。
- 誤操作や指とのズレが少ないか。

### 3. 操作の気持ちよさ

- 触った瞬間に反応があるか。
- 自分が画面を変えている感覚があるか。

### 4. 空気読み感

- 単なるパズルや当て物ではなく、人物・関係・状況を察する必要があるか。

### 5. 迷いの面白さ

- 選択肢や行動に意味のある迷いがあるか。
- 明白すぎる一択になっていないか。

### 6. 結果フィードバック

- 行動後の世界の変化が分かるか。
- Before / Afterや周囲の反応が理解できるか。

### 7. リプレイ性

- もう一度遊ぶ理由があるか。
- 高得点、自己ベスト、別シチュエーション、別行動を試したくなるか。

### 8. 年代適合性

- その年代で自然な状況・語彙・人間関係になっているか。
- 年齢を変えただけの使い回しになっていないか。

### 9. スマホ適合性

- 320px程度の縦長画面でも成立するか。
- 指で重要情報が隠れすぎないか。
- タップ領域、表示倍率、余白が適切か。

### 10. 世界観・安全性

- 「察して。」らしい簡潔さと余白を守っているか。
- 説教や人格評価になっていないか。
- 子ども向けモードでは特に安全で年齢に合うか。

## ハードゲート

次に該当する変更は、総合点が上がっても原則採用しません。

- 既存の確認済み操作を退行させる。
- typecheck / test / buildが失敗する。
- mainへ自動マージする。
- 子ども向け安全性を下げる。
- APIキーやSecretをクライアントへ露出する。
- 説明文を増やすことでしか初見理解を解決していない。
- スマホで主要操作が成立しない。

## 評価記録フォーマット

改善実験では最低限、次を残します。

```text
対象:
問題:
仮説:
変更:

Before:
- 対象軸: x/10
- 総合: xx/100

After:
- 対象軸: x/10
- 総合: xx/100

回帰:
自動検査:
Preview確認:
結論: 採用 / 却下 / 人間確認待ち
```

AIが主観評価する場合は、その点数だけで採用を決定せず、観察根拠を併記します。
