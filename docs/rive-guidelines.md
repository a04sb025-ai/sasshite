# Rive Integration Guidelines

この文書は、察して。でRiveを試験導入・採用するときの責務分離と命名ルールを定義します。

## 目的

Riveは「高品質な2Dアートを、同一キャラクターのまま自然に動かす」ために使います。

Reactコードで腕・脚・頭の座標を直接調整する代替として、Rive側にアート・リグ・ポーズ・アニメーションの責務を持たせます。

## 責務分離

### Reactが持つもの

- ゲーム進行
- 入力・ドラッグ判定
- 行動ID
- スコアリング
- タイマー
- Riveへ渡す意味的な状態

### Riveが持つもの

- キャラクターの見た目
- Bone / Rig
- standing / seatedなどのポーズ
- ポーズ間のアニメーション
- キャラクター内部の前後関係
- 状態に応じた表情や身体反応

### Reactに持たせないもの

- NPCの膝角度
- 腕のpixel座標
- 首の接続位置
- 座るアニメーションの各キーフレーム

これらはRive側で管理します。

## 状態と入力の命名

意味が分かる英小文字の名前を使い、Reactから見た契約を安定させます。

例:

- State Machine: `TrainScene`
- Bool: `success`
- Enum相当 / Number: `bagPosition`
- Trigger: `sitDown`

位置状態の例:

- `0 = seat`
- `1 = lap`
- `2 = floor`

実際の命名・型はRive実験で確定したらこの文書へ記録します。

## ファイル管理

採用する `.riv` はリポジトリ内で管理し、ファイル名から用途が分かるようにします。

候補:

- `src/assets/rive/player.riv`
- `src/assets/rive/train-scene.riv`

プロトタイプ段階では本番パスへ置かず、`prototypes/` 配下を利用して構いません。

## アート品質のゲート

Riveへ入れたから採用、にはしません。

最低限:

- 首・肩・腕・脚の接続が自然
- 左右の手足が意図せず消えない
- standing / seatedが同一人物に見える
- 320px程度の画面でも顔・姿勢・操作対象が読み取れる
- ポーズ変更で服や手足が破綻しない
- 背景・人物・操作物が独立している

アート品質NGの場合はReact側のCSSで補修しません。アート / リグ側で修正します。

## 最初の検証

最初はPlayer 1体だけを対象にします。

1. 基準アートを合格させる
2. パーツ分け
3. RiveでRig
4. standing / seatedを作る
5. 同一人物性と人体を目視確認
6. 必要ならReact Runtimeとの最小接続

電車背景、NPC、バッグを同時に作らないことで、Riveそのものの適性を小さく検証します。

## 導入判断

無料範囲で可能な検証を先に行います。有料プランや追加サービスが必要になる場合、契約前に目的・費用・代替案を確認します。

Riveがアート品質・制作負荷・スマホ運用のいずれかで不適切と分かった場合は、構造上得られた知見を残し、別の2Dリグ / アート制作手段へ切り替えます。
