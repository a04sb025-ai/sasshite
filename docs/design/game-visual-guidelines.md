# 察して — ゲームビジュアル設計ルール

## 目的

「どこで・誰が・何をしているか」を一瞬で理解でき、スマホ上で操作対象を迷わず見つけられることを最優先にする。キャラクターは丸く、やわらかく、親しみやすい。既存作品の固有キャラクター、UI、配色、構図は模倣せず、「察して」独自の視覚言語として統一する。

## 1. キャラクター

- 基本は3.5〜4頭身。
- 大きめの丸い頭、短く太めの手足、単純なシルエット。
- 顔は小さな目2つ＋小さな口を基本にし、情報量を増やしすぎない。
- 年齢・性別・服装の細部より、役割と姿勢が伝わることを優先する。
- プレイヤーは暖色系の共通アクセント色、NPCは低彩度の中性色を基本にする。
- 小さい表示でも「人物」「プレイヤー」「NPC」が判別できる形を優先する。
- リアルな骨格・筋肉・指・布のしわは描き込まない。

## 2. 色

- 背景は明るいニュートラル〜低彩度色。
- プレイヤーは暖色アクセントで一貫して識別できるようにする。
- NPCはプレイヤーより彩度を落とす。
- 操作対象は自然な物体色を保ちつつ、背景との明度差を十分に取る。
- 成功・失敗・注意色はUI側で補助し、背景画像内で過度に意味づけしない。
- 1画面の主要色は6〜8色程度に抑える。

## 3. 背景

場所は少数のランドマークで伝える。

- 電車: ベンチ、吊り革、窓またはドア、床境界。
- エレベーター: 扉、操作盤、狭い壁面。
- 食卓: テーブル、皿、料理、椅子。
- オンライン会議: 画面、机、カメラ・マイクを想起する最小限の要素。
- 帰り際: 出口、ゴミ箱、残置物など場面の中心となる要素。

装飾、広告、細かい模様、不要な人物、背景の小物は増やさない。

## 4. 構図

- スマホ縦画面を基準にする。
- プレイヤー、NPC、操作対象、移動先を中央寄りの安全領域に置く。
- 端からおおむね10〜12%以内には重要操作対象を置かない。
- `object-fit: cover` の軽い切り抜きがあってもゲーム成立に必要な要素を残す。
- 人物同士、人物と操作対象、小物同士の輪郭が重ならないようにする。
- 画面を見た1秒以内に状況の主役が分かることを目標にする。

## 5. 操作対象

- 通常時は世界観の一部として自然に見える。
- 背景と同化しないよう、輪郭・余白・明度差を確保する。
- タップ、ドラッグ、長押しの違いはHTML/CSS側の反応で示し、画像内に矢印や説明文字を描かない。
- ドラッグ対象は周囲に十分な余白を取り、別物体と接触させない。
- ドロップ先は視覚的に「置けそうな空間」として成立させる。

## 6. リアクション

- 成功・失敗は大げさな文章より、目線、体の向き、間隔、少しの姿勢変化で伝える。
- 表情差分は小さくする。
- NPCの反応は「見る」「少し近づく」「少し離れる」「体の向きを変える」程度を基本にする。
- 過剰な喜怒哀楽、マンガ記号、派手なエフェクトは避ける。

## 7. 画像生成共通ルール

毎回の生成プロンプトで以下を明示する。

- オリジナルの2Dモバイルゲーム用イラスト。
- 3.5〜4頭身の丸い簡略キャラクター。
- プレイヤーの服装・髪型・比率・共通色を固定。
- カメラ位置、人物数、配置、操作対象、空き領域を具体的に指定。
- 重要要素を中央安全領域へ配置。
- 操作対象を他の人物や線で隠さない。
- 画像内テキスト、ロゴ、UI、矢印、透かしは禁止。
- 背景は最小限のランドマークのみ。
- 陰影とテクスチャを控えめにする。
- 写実、3D、アニメ作品風、編集イラスト風、既存作品の模倣を避ける。

## 8. 電車ステージの基準構図

- 縦長画面。
- 左下に座ったプレイヤー。
- そのすぐ右の隣席にバッグ。
- 右寄りに立つNPC。
- プレイヤーの膝がバッグと重ならず見える。
- 座席下〜画面下部にバッグを置けそうな空いた床を確保する。
- 電車であることはベンチ、吊り革、窓またはドアで伝える。
- 人物はプレイヤーとNPCの2人だけを基本とする。
- バッグは画面上の最重要操作物として、輪郭全体と周囲余白を確保する。

既存の `src/components/SceneArtwork.tsx` の train ヒット領域を基準に、画像生成時も以下の位置関係から大きく外さない。

- player: left 9%, top 49%, width 29%, height 34%
- bag: left 39%, top 57%, width 26%, height 19%
- lap: left 18%, top 63%, width 25%, height 18%
- floor: left 10%, top 81%, width 78%, height 16%

## 9. 実装方針

ゲーム進行・採点ロジックは画像から独立した現在の構成を維持する。まず1ステージでビジュアルを検証し、採用後に他ステージへ展開する。背景画像の構図を変えた場合だけヒット領域を調整し、画像だけに操作判定を依存させない。
