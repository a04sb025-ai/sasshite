# 自律開発フロー

この文書は、Codex / ChatGPTが「察して。」を継続的に改善し、公開品質へ近づける標準ループと安全境界を定義します。

## 目的

ユーザーが毎回、実装できる粒度まで仕様を書かなくても、次の循環をAI側で進めます。

ユーザーの目的・感想 → 現状分析 → 公開品質の未達確認 → 改善候補 → 仮説 → 小さな実装 → 自動検査 → 評価 → 安全ならmain反映 → 次の改善

ユーザーの主な役割は、方向性、好み、止めたいこと、時々の実機感想です。

## AI Game Director v1

自律改善は同じモデルが担当しても、Director / Reviewer / Engineer / Evaluator の判断段階を分離します。

### Director

- 最新main、open PR、`docs/release-readiness.md` を読む。
- 公開品質への改善余地を最大3件挙げる。
- 影響範囲、期待効果、回帰リスクを比較し、1件だけ選ぶ。

### Reviewer

- `docs/evaluation-rubric.md` と公開品質ゲートに沿って現状を評価する。
- 問題、仮説、成功条件、回帰条件を実装前に明示する。

### Engineer

- 1サイクル1目的を守る。
- 必要最小限の変更とテストを行う。
- 高リスク領域へ踏み込まない。

### Evaluator

- 変更前後を同じ基準で比較する。
- `typecheck` / `test` / `build` を通す。
- 改善と合理的に判断できない変更は残さない。

## 実行方法

`.github/workflows/ai-game-director.yml` が実行正本です。

### 手動 analyze

コードを変更せず、改善候補と仮説だけを出します。

### 手動 implement

1件だけ実装します。`auto_merge=true` の場合、安全ゲートをすべて通った候補はmainへ自動マージできます。

### 定期実行

毎日1回、公開品質ゲートの未達項目から安全に改善可能な最重要1件を選びます。安全ゲートを通った低リスク改善は自動マージします。

定期実行は大量変更のためではありません。1日に1つ、小さく確実に良くすることを狙います。

## 自動マージできる範囲

`docs/release-readiness.md` に定義した低リスク範囲だけです。現在の機械的ガードは次を含みます。

- 1回1改善
- 最大8ファイル
- workflow / ガバナンス / 依存 / lockfile / Cloudflare設定 / imagegen / public assets は変更禁止
- Secret、課金、広告、外部送信、ユーザーデータ保存、子ども安全ルール緩和は禁止
- `git diff --check` 成功
- `npm run typecheck` 成功
- `npm test` 成功
- `npm run build` 成功

これらを通った変更は、ユーザーの都度承認なしでmainへ反映してよいものとします。

## 人間承認を残す領域

- Secret / API key / 権限
- 課金・広告
- 個人情報・ユーザーデータ保存
- 外部データ送信
- 子ども向け安全設計の緩和
- 大規模なゲーム目的・世界観変更
- 高額または反復的な画像/API利用
- デプロイ基盤やworkflowの破壊的変更

## 公開品質への成長

AIは単に機能を増やすのではなく `docs/release-readiness.md` の未達を減らします。

優先順位は原則として次です。

1. ゲームが最後まで正常に遊べる
2. 初見理解と操作感
3. 結果・スコア・リプレイ性
4. スマホ安定性
5. 年代別モードとコンテンツ量
6. 子ども向け品質
7. 細かな演出・磨き込み

公開判定は `NOT_READY` / `PREVIEW_READY` / `PUBLIC_READY` の3段階で扱います。

## 問題生成ループ

ゲーム本体の改善とシチュエーション生成は分離します。問題生成は少量バッチで行い、年代適合、重複、迷いの質、安全性、操作可能性を確認してから採用します。

## ユーザーが介入したとき

ユーザーの最新の明示指示を最優先します。「これは違う」「この方向にしたい」「ここは触らないで」といったフィードバックは、次回以降の自律改善ルール・優先順位へ反映します。
