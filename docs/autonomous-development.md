# 自律開発フロー

この文書は、Codex / ChatGPTが「察して。」を継続的に改善する際の標準ループと安全境界を定義します。

## 目的

ユーザーが毎回、実装できる粒度まで仕様を書かなくても、次の循環をAI側で進められる状態を目指します。

ユーザーの目的・感想 → 現状分析 → 改善候補 → 仮説 → 小さな実装 → 自動検査 → Preview → 評価 → 採用 / 却下 → 記録 → 次の改善

ユーザーの主な役割は、方向性、好み、OK / NG、Android実機での最終感触の判断です。

## AI Game Director v1

自律改善時は、ひとつのAIが無制限に変更するのではなく、次の役割を順番に実行します。同じモデルが担当しても、判断段階を分離してください。

### 1. Director

- `AGENTS.md`、`docs/current-plan.md`、`docs/game-vision.md`、関連設計、最新main、関連PRを読む。
- 現在のゲームで改善余地を最大3件挙げる。
- 影響範囲、期待効果、回帰リスクを比較する。
- 1サイクルでは最重要1件だけを選ぶ。

### 2. UX / Game Reviewer

- `docs/evaluation-rubric.md` に沿って現状を評価する。
- 「機能が増える」ではなく、どの評価軸を改善するか明示する。
- スマホ画面、初見理解、操作反応、Before / After、リプレイ性を重視する。

### 3. Engineer

- 変更前に仮説と受け入れ条件を記録する。
- 1PR 1目的を守る。
- 既存の回帰基準を壊さない。
- typecheck / test / build を実行する。
- UI変更では可能なら自動ブラウザ検査とスクリーンショットを残す。

### 4. Evaluator

- 変更前後を同じ評価基準で比較する。
- テスト成功だけで「改善」と判定しない。
- 総合評価または対象軸が改善せず、別の重要軸を悪化させる変更は採用しない。
- 判断できない視覚・操作品質はPreviewで人間確認へ送る。

## 1改善サイクル

1. 最新mainと関連PRを確認する。
2. 現在のタスクを壊さない範囲を確定する。
3. 改善候補を最大3件作る。
4. 最重要1件を選ぶ。
5. 「問題 / 仮説 / 変更 / 成功条件 / 回帰条件」を書く。
6. 専用ブランチで実装する。
7. `npm run typecheck`、`npm test`、`npm run build` を通す。
8. UIならBefore / Afterまたは同条件スクリーンショットを残す。
9. 評価基準で再評価する。
10. 改善ならPRを作る。悪化ならrevertまたはPRを閉じる。
11. `docs/current-plan.md` または関連記録へ結果を残す。
12. mainへは自動マージしない。

## 改善ログ

自律改善を複数回行う段階では、次の情報をGitHub上に残します。

- 実験ID
- 日付
- 対象
- 問題
- 仮説
- 変更内容
- Before評価
- After評価
- 自動検査結果
- Preview / Android確認結果
- 採用 / 却下
- 却下理由

却下した案も記録し、同じ失敗を短期間に繰り返さないようにします。

## 自動化の段階

### Phase 1: 人間承認付き1サイクル

AIが1件だけ改善してPRを作り、人間がAndroid Previewで確認します。

### Phase 2: 3実験まで

1つずつ独立した仮説として最大3実験を行い、悪化した案を残さず、最良候補をPRにまとめます。

### Phase 3: 定期実行

十分な回帰テストと評価ログが揃ってから、定期的に改善候補を作る仕組みを導入します。定期実行でもmainへ自動マージしません。

## 絶対に自律化しない判断

次は人間承認を必要とします。

- mainへのマージ
- 本番公開に直結する破壊的変更
- 課金、広告、外部送信、ユーザーデータ保存の新規導入
- APIキー / Secretの追加や公開範囲変更
- 子ども向け安全設計の緩和
- 大きな世界観変更
- 高額または反復的な画像 / AI API利用

## 問題生成ループ

ゲーム本体の改善とシチュエーション生成は分離します。

問題生成AIは、不足年代・不足カテゴリを確認し、少数の候補を作成します。別のレビュー段階で `docs/age-modes.md` に照らして年代適合、重複、迷いの質、安全性、操作可能性を確認し、合格した問題だけを追加します。

大量の問題を一度に生成・採用しません。まず5件程度を生成し、レビューを通ったものだけ追加する小さなバッチを基本とします。
