# 高速開発モード: 遊べる原型

この文書は、公開品質を細かく磨く前に「察して。」のゲームとしての芯を最短で形にするための優先順位です。

## 最優先方針: まず今あるテーマをゲームにする

新しい問題数を増やすことより、**現在すでに存在するテーマ / シチュエーションを、1つずつ「実際に遊んで面白い」レベルへ改善することを最優先**とする。

当面、新規シチュエーションの大量追加は禁止する。既存テーマに明確な遊べない問題が残っている間、AI Game Directorはコンテンツ数を増やすことを改善成果として扱わない。

## 参照実装: 電車のバッグ

他テーマへ展開するときは、現在の電車バッグの操作思想を**最優先の参照実装**とする。

電車で合意したゲーム体験は次の通り。

1. 問題文で状況を説明しすぎない。
2. 「あなたはこれです」「ここを押す」「正解はここ」といったガイドを画面上に置かない。
3. 情景そのものから、誰が困っているか、何が邪魔か、何を動かせそうかを察する。
4. 操作対象そのものを直接つかむ / タップする。別枠の選択肢ボタンを押させない。
5. バッグならバッグを直接ドラッグし、膝・床など情景の中の場所へ置く。
6. 行動後は人物の位置・表情・物の位置・Before / Afterで世界が反応する。
7. 結果文は必要最小限にし、基本は絵の変化から意味が分かるようにする。
8. 正解は一つに固定しすぎず、複数のもっともらしい行動に異なる評価を持たせる。
9. 「待つ / 何もしない」も状況によっては一つの行動として扱う。

この思想を他テーマへ移植する。見た目だけ絵にしても、この操作思想を満たしていなければ「画像型へ変換済み」と判定しない。

## 明確なNG: 絵にした三択

次は**三択クイズを絵に置き換えただけ**なので禁止する。

- 人物の下に「つくる こ」「みている こ」のような説明ラベルを常時表示する。
- 画面内に「わたす」「おく」「手伝う」など、行動名そのものを書いた大きなボタンを並べる。
- アイコン付きボタンを絵の中へ置き、実質的に二択 / 三択を選ばせる。
- 選択肢ボタンの位置だけを画像上へ移し、「画像をタップするゲーム」とみなす。
- 正解対象だけ色・枠・点滅・矢印で露骨に示す。

**判断基準:** 文字を全部隠しても、その情景と操作だけで一応プレイできるか。できなければ未完成とする。

## 「察して。」の基本操作

1. まず情景を見る。
2. 人物の表情、姿勢、距離、持ち物、空いている場所、周囲の反応などから状況を察する。
3. プレイヤーが「ここかな」「これかな」と思った**画像内の人物・物・場所を直接タップする、物をドラッグする、または待つ**。
4. 選択肢の文章で正解を説明するのではなく、人物・物・場面のBefore / Afterや反応によって結果を返す。
5. 必要ならその後に短い結果文を出す。

正解箇所を常時光らせたり、矢印や長い説明で答えを先に教えたりしない。ただし、何を操作できるか全く理解できない状態にもせず、触ったときの反応、自然な視線誘導、形や配置で操作可能性を伝える。

既存の三択データは削除を急がない。シチュエーション、行動候補、採点根拠の**裏側データ**として再利用し、画面上からは順次消していく。

## 原型の完成条件

### P0: 既存テーマのプレイアブル化

- 現在存在する主要テーマを一覧化し、1つずつ遊べる状態へする。
- 各テーマで、情景から状況を理解できる。
- 主操作は画像内タップ / ドラッグ / 待つのいずれかである。
- 操作対象は基本的に「物そのもの / 人物そのもの / 情景内の場所」である。
- 操作すると世界が反応し、Before / Afterが分かる。
- 説明文の選択肢だけでゲームが完結しない。
- 行動名を書いたボタンを常時見せない。
- 文字ラベルを消しても遊べる構図を目指す。
- 間違った場所を触った場合も、可能なら即座に大きな「不正解」を出すより世界の反応で違和感を返す。

### P1: ゲームループ

- 年代を選択してプレイを開始できる。
- 幼稚園、小学校低学年、小学校高学年、中学生、高校生、大学生、社会人の7年代をデータモデルとして扱える。
- 選択した年代の問題プールから1プレイ約10問を構成できる。
- 問題数が10未満の開発途中モードは安全に利用可能数だけ出題し、未完成を隠さない。
- 1問ずつ回答して最後まで完走できる。

### P2: リプレイループ

- プレイヤーの行動に応じたスコアがある。
- 1プレイ終了時に100点満点を基本とした結果を表示する。
- 自己ベストを端末内で保持できる。
- 「もう一度」で新しい問題構成または順番を楽しめる。
- 同じ選択肢の暗記だけで満点になる設計へ固定しない。
- 同じ情景でも、触る場所・動かす先・待つなど複数のもっともらしい行動を持たせられる。

### P3: 年代差が体験できる

原型では全350問を待たない。既存テーマのプレイアブル化を優先し、その後に性格の離れた次の3年代を代表サンプルとして磨く。

1. 幼稚園: 絵・短い言葉・タップ/ドラッグ中心。人格を採点しない。
2. 中学生: 教室、友人、部活、先輩後輩など微妙な人間関係。
3. 社会人: 職場、会議、上司/後輩、公共空間など状況依存の判断。

### P4: スマホで遊べる

- 320px程度から主要操作が成立する。
- タップ対象は原則44px以上。ただし見た目として透明な巨大正解ボタンを置いて答えを露骨にしない。
- 主要操作が画面外に隠れない。
- 操作直後に反応がある。
- 結果画面から迷わず再プレイできる。

## AI Game Directorの改善優先順位

高速開発中は次の順番で改善する。

1. **現在の「幼稚園・積み木」を最初の是正対象にする。** 「つくる こ / みている こ / わたす / おく」の常時ラベルと行動ボタンをなくし、積み木そのものや人物・作品の位置を直接操作する形へ直す。
2. 既存テーマで三択クイズまたは「絵にした三択」になっているものを、電車バッグ方式の画像内タップ / ドラッグ / 待つ型へ変換する。
3. 既存テーマの「何をすればいいか全く分からない」「対象物が判別できない」「操作しても反応が分からない」を直す。
4. Before / Afterと人物の反応を強化する。
5. 既存テーマをスマホで最後まで遊べるようにする。
6. スコア・自己ベスト・再プレイを整える。
7. 上記が十分成立してから新しいシチュエーションを少量ずつ追加する。

## 1テーマ変換時の必須レビュー

AI Game Directorはテーマを「変換済み」とする前に、必ず次を自己チェックする。

- 電車バッグと同じく、操作対象を直接触っているか。
- 行動名のボタンを選んでいないか。
- 画面上の文字が答えを説明していないか。
- Beforeだけを見て「何か起きている」と察せるか。
- 行動後に絵として変化するか。
- 複数の自然な行動を作れる余地があるか。
- Androidの指操作で成立するか。

1つでも重大な未達があれば、新規テーマ追加へ進まない。

## 高速開発中に後回しにするもの

上記に明確な未達がある間は、次を優先課題にしない。

- 新規問題数を増やすだけの変更
- 三択 / 四択テキスト問題の追加
- 「絵にした三択」の追加
- 数px単位の装飾調整
- 大量の背景画像生成
- 全年代30〜50問の一括生成
- AI自由回答判定
- ランキング/アカウント/オンライン機能
- 収益化
- 大規模なアニメーション刷新

## 高速開発の終了条件

現在ある主要テーマが電車バッグと同じ操作思想で画像内操作を中心に一連のプレイとして成立し、P0〜P4がコード・自動テスト上で概ね成立し、固定本番URLで人間が一連のプレイを試せる状態になったら、高速開発モードを終了候補とする。

その後は `docs/release-readiness.md` を主基準に戻し、問題品質、年代別コンテンツ量、Android実機品質、演出、リプレイ性を継続的に磨く。
