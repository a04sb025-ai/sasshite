# 高速開発モード: 遊べる原型

この文書は、公開品質を細かく磨く前に「察して。」のゲームとしての芯を最短で形にするための優先順位です。

AI Game Directorは高速開発モード中、細かな見た目調整より未達の上位マイルストーンを優先します。1サイクルでは1つのまとまった改善だけを行い、検査を通してからmainへ反映します。

## 原型の完成条件

### P0: ゲームループ

- 年代を選択してプレイを開始できる。
- 幼稚園、小学校低学年、小学校高学年、中学生、高校生、大学生、社会人の7年代をデータモデルとして扱える。
- 選択した年代の問題プールから1プレイ約10問を構成できる。
- 問題数が10未満の開発途中モードは安全に利用可能数だけ出題し、未完成を隠さない。
- 1問ずつ回答して最後まで完走できる。

### P1: リプレイループ

- プレイヤーの行動に応じたスコアがある。
- 1プレイ終了時に100点満点を基本とした結果を表示する。
- 自己ベストを端末内で保持できる。
- 「もう一度」で新しい問題構成または順番を楽しめる。
- 同じ選択肢の暗記だけで満点になる設計へ固定しない。

### P2: 年代差が体験できる

原型では全350問を待たない。まず性格の離れた次の3年代を代表サンプルとして優先する。

1. 幼稚園: 絵・短い言葉・タップ/ドラッグ中心。人格を採点しない。
2. 中学生: 教室、友人、部活、先輩後輩など微妙な人間関係。
3. 社会人: 職場、会議、上司/後輩、公共空間など状況依存の判断。

各代表年代に複数シチュエーションを用意し、年代を変える意味が実感できること。残り4年代はデータモデルと導線を先に成立させ、代表3年代の手応えを確認しながら増やす。

### P3: 操作のバリエーション

原型の段階で全問を文章4択にしない。

- タップ
- ドラッグ
- 行動選択
- 何もしない/待つ

など既存アーキテクチャで安全に実装できる操作を混ぜる。AI自由入力は原型の必須条件にしない。

### P4: スマホで遊べる

- 320px程度から主要操作が成立する。
- タップ対象は原則44px以上。
- 主要ボタンが画面外に隠れない。
- 操作直後に反応がある。
- 結果画面から迷わず再プレイできる。

## 高速開発中に後回しにするもの

上記P0〜P4に明確な未達がある間は、次を優先課題にしない。

- 数px単位の装飾調整
- 大量の背景画像生成
- 全年代30〜50問の一括生成
- AI自由回答判定
- ランキング/アカウント/オンライン機能
- 収益化
- 大規模なアニメーション刷新

## 高速開発の終了条件

P0〜P4がコード・自動テスト上で概ね成立し、固定本番URLで人間が一連のプレイを試せる状態になったら、高速開発モードを終了候補とする。

その後は `docs/release-readiness.md` を主基準に戻し、問題品質、年代別コンテンツ量、Android実機品質、演出、リプレイ性を継続的に磨く。
