# 公開品質ゲート

この文書は「察して。」が公開できるレベルに達したかをAIと人間が共通基準で判断するための正本です。

AI Game Directorは定期実行時、この文書の未達項目から、1回で安全に改善できる最重要1件を選びます。

## 公開の最低条件

### 1. ゲームとして成立

- 初見で何をするゲームか理解できる。
- 1プレイが最後まで完走できる。
- プレイヤーの操作に明確な反応がある。
- Before / Afterまたは行動結果が理解できる。
- もう一度遊ぶ理由がある。
- スコアまたは結果がプレイヤーの行動と結びついている。

### 2. 年代別モード

最終目標は次の7モード。

- 幼稚園
- 小学校低学年
- 小学校高学年
- 中学生
- 高校生
- 大学生
- 社会人

公開初期版は、すべてを30〜50問まで完成させる必要はない。ただし未完成モードを完成済みのように見せない。

各公開モードは原則として次を満たす。

- その年代らしいシチュエーションが複数ある。
- 1回約10問を重複しすぎず構成できる。
- 複数の行動・結果があり、単純暗記だけで満点になりにくい。
- 年齢に合わない文章量や題材を避ける。

### 3. 子ども対応

- 低年齢では文章依存を減らす。
- 小さすぎるタップ対象を作らない。
- 子ども本人の人格を否定する結果文を出さない。
- 個人情報入力を要求しない。
- 子ども向けモードで外部チャットを提供しない。
- AI自由入力を導入する場合は、低年齢モードでは別途安全設計を通す。

### 4. スマホ品質

- 320px程度の縦長画面で主要操作が成立する。
- Android実機で致命的なレイアウト崩れがない。
- ドラッグ、タップ、長押しなど主要操作が安定する。
- Canvas / viewport / DPR差による重大な座標ずれがない。
- 画面外に主要操作が隠れない。

### 5. 技術品質

mainは常に以下を満たすことを目標とする。

- `npm run typecheck` 成功
- `npm test` 成功
- `npm run build` 成功
- Secretをクライアントへ埋め込まない
- 重大な既知回帰を放置しない

### 6. 自律改善品質

- 1サイクル1仮説を基本とする。
- 変更理由と対象評価軸を説明できる。
- 改善不能または悪化と判断した変更を無理に残さない。
- 同じ失敗を反復しないよう記録を残す。
- 高リスク領域は自動マージ対象にしない。

## 自動マージ可能な範囲

次をすべて満たす低リスク改善は、人間の都度承認なしでmainへマージしてよい。

- 1改善・8ファイル以内。
- workflow、依存関係、Secrets、Cloudflare設定、公開アセット生成経路を変更しない。
- 課金、広告、外部送信、ユーザーデータ保存を新規導入しない。
- 子ども向け安全ポリシーを緩和しない。
- `typecheck`、`test`、`build` がすべて成功する。
- AI Game Director自身が対象評価軸の改善を合理的に説明できる。

## 人間確認を必須にする範囲

- Secret / API key / 権限変更
- 課金・広告
- 個人情報・ユーザーデータ保存
- 外部へのデータ送信
- 子ども向け安全設計の緩和
- 大規模な世界観・ゲーム目的変更
- 高額または反復的な画像/API利用
- デプロイ基盤やworkflowの破壊的変更

## 公開判定

AIは「公開可能」と自己申告してよいが、次を区別する。

- `NOT_READY`: 明確な未達がある。
- `PREVIEW_READY`: 公開候補として人間が実機確認できる。
- `PUBLIC_READY`: 自動検査と主要公開基準を満たし、既知の重大問題がない。

最初の公開後も、この文書を終点ではなく継続改善の基準として使う。
