# 年代別モード設計

「察して。」は、年代によって空気を読む場面そのものが変わることをゲームの中心に置きます。

## 共通構造

- 7つの年代モードを用意する。
- 各年代は最終的に30〜50シチュエーションを目標にする。
- 1プレイは原則約10問。
- 問題プールから偏りを抑えて抽選し、毎回同じ10問にならないようにする。
- 各シチュエーションは複数の行動候補または操作結果を持てる。
- 単純な正誤だけでなく、行動ごとの評価差を持てる構造にする。
- 同じ場面を丸暗記するだけで満点にならないよう、将来的に条件差・行動差を追加できるようにする。

シチュエーションはゲームコードへ巨大な条件分岐として埋め込まず、可能な限りデータとして管理します。

## 推奨シチュエーションデータ

将来の問題データは、少なくとも次を表現できる形を目指します。

```text
id
ageMode
category
location
people / relationships
situation
hiddenCue
interactionType
actions / outcomes
scoreEffects
difficulty
resultFeedback
variants
safetyNotes
```

既存の `src/data/` と採点ロジックの分離方針を維持し、年代追加のたびに巨大な専用コンポーネントを複製しないでください。

## 1. 幼稚園

### 主な世界

- 園庭
- 教室
- おもちゃ
- おやつ
- 給食
- 家族
- 先生
- 友達との遊び

### 空気の例

- 順番を待っている子がいる。
- おもちゃを使いたそうな子が見ている。
- 一人でいる子がいる。
- 片付けの時間になった。
- 友達が作ったものを触りたくなった。

### UI / 文言

- 絵、タップ、ドラッグを中心にする。
- 文章は極力短くする。
- ひらがな中心を基本候補にする。
- 点数で強く競争させるより、世界の反応を分かりやすくする。
- 「空気が読めない」など本人を評価する文言は禁止。

## 2. 小学生低学年

### 主な世界

- 教室
- 休み時間
- 給食
- 登下校
- 公園
- 習い事
- 家族

### 空気の例

- 消しゴムを落とした子がいる。
- 給食のおかわりが残り一つ。
- 友達が遊びに入りたそうにしている。
- 掃除中に一人だけまだ片付けている。
- 列に途中から友達が来た。

### UI / 文言

短文 + 直接操作を中心とし、長い状況説明は避けます。

## 3. 小学生高学年

### 主な世界

- クラスのグループ
- 委員会
- クラブ
- 班行動
- 放課後
- 友達同士の約束

### 空気の例

- 班で一人だけ意見を言えていない。
- 友達二人が少し気まずそう。
- グループで決めた予定に遅れそうな子がいる。
- 先生に注意された友達へ周囲がどう接するか迷っている。

複数の自然な選択肢を増やし始めます。

## 4. 中学生

### 主な世界

- クラス
- 部活
- 先輩後輩
- グループ
- 学校行事
- メッセージ / グループ連絡

### 空気の例

- 先輩と友達の意見が違う。
- グループの一人だけ話に入れていない。
- 部活終了後、まだ片付けをしている人がいる。
- 友達二人がケンカしたあと両方から話を聞かれる。

「正しい行動」より、関係性と距離感を考える問題を増やします。

## 5. 高校生

### 主な世界

- クラス
- 部活
- 友達
- 恋愛
- バイト
- 進路
- 学校行事

### 空気の例

- 友達同士の会話に入りたい人が近くにいる。

- グループの予定決めで一人だけ返信していない。

明確な唯一解をさらに減らします。

## 6. 大学生

### 主な世界

- 授業
- ゼミ
- サークル
- バイト
- 友人関係
- 飲食を伴う集まり
- 就活

### 空気の例

- 会計で先輩が多めに払おうとしている。

- サークルの集まりから帰りたそうな人がいる。

## 7. 社会人

### 主な世界

- 会議
- 上司 / 同僚 / 後輩
- 顧客 / 取引先
- オンライン会議
- 休憩
- エレベーター
- 電車
- 懇親の場

### 空気の例

- 会議が終わりそうなときに追加意見を求められる。
- 誰かが資料を配っている。
- エレベーターへ少し離れた人が向かってくる。
- オンライン会議で発言者がかぶる。
- 退勤しようとしていると近くで困っている人がいる。

最も「どれも完全な正解ではない」状況を増やせます。

## 問題の多様性

各年代30〜50問を、同じ種類の問題で埋めません。

カテゴリ、場所、関係性、操作形式、難易度の偏りを確認します。

例:

```text
友達関係 12問
集団行動 8問
知らない人 5問
先生 / 先輩等 7問
家族 5問
その他 3問
```

この配分は年代ごとに変えて構いません。

## 1プレイ10問の抽選

将来的な抽選では、完全ランダムだけでなく次を考慮します。

- 同じカテゴリばかり連続させない。
- 直前のプレイと同じ10問になりにくくする。
- 難易度を混ぜる。
- 操作形式を混ぜる。
- 未プレイ問題を少し優先できるようにする。

自己ベストを競う場合、問題セット差による不公平感が強くならないようスコア設計と合わせて調整します。

## AI問題生成時の品質ゲート

AIが新しいシチュエーションを生成するときは、候補ごとに次を確認します。

1. 対象年代で実際に起こりそうか。
2. 既存問題と本質的に重複していないか。
3. 一目で正解が分かる道徳問題になっていないか。
4. 複数のもっともらしい行動があるか。
5. 絵や操作で表現できるか。
6. 子ども向け安全性を満たすか。
7. 人格ではなく行動を評価しているか。

一度に大量採用せず、まず少量を作り、レビューしてから問題プールへ追加します。
